# Nebula Classroom

The website of Nebula's classroom in Tetovo: the room, the four ways to book it,
and a calendar where teachers request hours. Albanian (`/`), Macedonian (`/mk`)
and English (`/en`). Next.js 16 + Tailwind v4 + shadcn, running on Cloudflare
Workers (OpenNext) with a D1 database.

- What we're building and in which order: [SPEC.md](SPEC.md)
- The design every page follows: [design/Website.pdf](design/Website.pdf)

## Running it

```bash
corepack pnpm install
corepack pnpm db:migrate:local   # creates the local database (.wrangler/state)
corepack pnpm dev                # http://localhost:3000
```

| Command | What it does |
|---|---|
| `corepack pnpm dev` | The site with live reload. Bookings go to the local database. |
| `corepack pnpm preview` | Builds the real Worker and runs it on workerd (Cloudflare's runtime) at http://localhost:8787. |
| `corepack pnpm typecheck` / `lint` | TypeScript and ESLint. |
| `corepack pnpm db:generate` | After editing `lib/db/schema.ts`: writes the next SQL migration into `migrations/`. |
| `corepack pnpm db:migrate:local` | Applies migrations to the local database. |
| `corepack pnpm images` | Remakes the icons and the share images (`public/og/*.png`) after the headline or icon changes. |
| `corepack pnpm admin:add -- --email ana@example.com --name "Ana"` | Adds a staff account to the admin (asks for the password), or sets a new password. Add `--remote` for the live database. |
| `corepack pnpm deploy` | Checks the production settings, builds and deploys (SPEC step 5). |

Local secrets live in `.dev.vars` (Turnstile's test secret, which always passes;
Better Auth's secret). The admin is at http://localhost:3000/admin.

## One booking, through the code

A teacher on `/en` picks Tuesday 10 November, 12:00–14:00, and sends the form.

1. **The page.** `app/[locale]/page.tsx` renders the home page for `en`; the
   booking section is `features/booking/booking-section.tsx`, which puts the
   headline on the page and hands the moving parts to
   `components/booking-planner.tsx`.
2. **Free hours.** The planner's `use-availability.ts` calls
   `GET /api/availability` (`app/api/availability/route.ts`), which asks
   `server/availability.ts` for the taken hours in D1 and the booking window
   from `model/rules.ts` (24 hours' notice, 6 months ahead).
3. **Picking.** Tapping the 10th and then 12:00 and 13:00 goes through
   `model/selection.ts` (the reducer that decides what a tap means). The month
   grid is `components/month-calendar.tsx`, the hours `components/hour-grid.tsx`,
   and "Your pick: 12:00–14:00 · 2 hours" is `components/pick-summary.tsx`.
   `checkPlan()` in `model/rules.ts` enables **Continue** once the pick meets the
   plan's minimum.
4. **Details.** `components/details-form.tsx` checks the fields with
   `model/request.ts` (the same schema the server uses), gets a Turnstile token
   and posts to `/api/bookings`.
5. **Saving.** `app/api/bookings/route.ts` checks the schema and Turnstile
   (`server/protection.ts`), then `server/create-booking.ts` checks the plan
   again, the rate limit, and the free hours, and writes the booking, its
   sessions and one `held_hours` row per hour in one D1 batch. The `held_hours`
   key (day + hour) makes it impossible for two requests to hold the same hour.
6. **Done.** The answer carries a reference code; the card shows it and says
   we'll call. If someone took the hours a moment earlier, the API answers
   409 and the calendar reloads with a note.
7. **The admin.** The request shows on `/admin` under "Në pritje"
   (`app/admin/(panel)/page.tsx` → `features/admin/bookings/`). Staff call the
   number, then "Konfirmo" in the row's ⋯ menu runs `setStatusAction`
   (`features/admin/actions.ts`), which checks the session and calls
   `setBookingStatus` in `features/booking/server/manage-booking.ts`. Declining
   deletes the booking's `held_hours` rows, which frees the hours on the public
   calendar at once. Searching the code finds the booking when the visitor
   calls back.

## Languages

All text is in `lib/i18n/dictionaries/`. `en.ts` defines the keys; `sq.ts` and
`mk.ts` must have the same ones (TypeScript checks). Month and weekday names are
in `lib/i18n/calendar-names.ts`, because browsers don't all know Albanian and
Macedonian dates. Albanian pages have no prefix; `next.config.ts` maps them.

## Fonts

Archivo (the design's font) has no Cyrillic, so Macedonian letters use Inter
Tight. `app/[locale]/layout.tsx` builds the font stack; don't add next/font's
`variable` option back, or Arial catches the Cyrillic letters first.
